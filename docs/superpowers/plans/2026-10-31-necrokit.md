# NecroKit Implementation Plan

> **For agentic workers:** Use this plan task-by-task. Keep the two applications independent while preserving the shared-core contract.

**Goal:** Build a Skeleton Crew project with one reusable evidence-and-revival foundation and two distinct TypeScript applications.

**Architecture:** `@necrokit/core` owns normalized evidence, deterministic rules, scoring, reports, and revival plans. Package Graveyard owns package-registry adapters; Repo Reaper owns GitHub adapters. Both apps use fixtures first and may add safe live adapters later.

**Tech Stack:** TypeScript, Node.js 22+, pnpm workspaces, React/Vite clients, Zod, Vitest, fast-check, SQLite, npm registry API, deps.dev API, GitHub REST API.

**Spec:** `.kiro/specs/core-platform/requirements.md`, `.kiro/specs/package-graveyard/requirements.md`, `.kiro/specs/repo-reaper/requirements.md`.

## Global Constraints

- The main repository must contain two separate application folders.
- The root `.kiro` directory must remain tracked.
- The judging path must work without secrets, paid services, or live API availability.
- Deterministic evidence and rules are the source of truth; LLM summaries are optional.
- No automatic code changes, pull requests, authentication, or private-repository support.

## Review Focus

- Missing evidence: show an explicit unavailable state instead of inventing a score.
- Stable old package: do not classify age alone as abandonment.
- Rate limits and timeouts: fall back to recorded fixtures and preserve the failure reason.
- Malformed API payload: reject at the adapter boundary without crashing the report.
- Shared-core drift: verify both apps compile against the same core without app-specific changes.
