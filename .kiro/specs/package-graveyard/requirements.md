# Package Graveyard requirements

1. A user can enter a package name or load a fixture package manifest.
2. The application displays package and dependency findings with evidence.
3. The application distinguishes stable-old packages from abandoned packages.
4. The application displays an explainable score and severity breakdown.
5. The application generates a prioritized upgrade, replacement, or fork plan.
6. The fixture path works without network access or API keys.
7. Live calls fail safely and display an actionable unavailable state.
